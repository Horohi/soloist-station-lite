# Soloist для Яндекс Станций

Клиент Spotify Connect для Яндекс Станций на Linux ARM64 (`aarch64`): голосовое управление и поиск музыки через Алису, синхронизация громкости с колонкой, управление кнопками и LED-эквалайзер.

## Поддерживаемые модели

Колонки с 64-битным ядром Linux (`aarch64`):

| Модель | Платформа |
| --- | --- |
| Станция Лайт 1 | `yandexmicro` |
| Станция Лайт 2 | `plum`, `yandexplum` |
| Станция Мини 1, 2, 3, 3 Про | `yandexmini`, `yandexmini_2`, `bergamot`, `pickle` |
| Станция 2 | `yandexmidi` |
| Станция Миди | `cucumber` |

Станция Макс (`yandexstation_2`) работает на Android и не поддерживается Linux-установщиком (`soloist update` отклоняет обновление).

## Установка

Для работы нужен root-доступ к колонке (ADB) и ключ Spotify Soloist API (подписка Spotify Premium). Для голосового поиска по каталогу дополнительно потребуются `Client ID` и `Client Secret` из [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).

### YAM v2

Пакеты `.yampkg` используют раздельные каталоги `$YAM_ROOT/share/horohi.soloist`, `$YAM_ETC/horohi.soloist` (`config.env`, `spotify_api.conf`, `spotify-network.conf`) и `$YAM_VAR/horohi.soloist`. Если ранее стояла Standalone-версия в `/data/opt/soloist`, установщик перенесёт ключи и настройки при обновлении.

```bash
# Установка из каталога YAM v2
yam install horohi/soloist

# Или установка скачанного пакета из Releases
yam install horohi-soloist-<версия>-<платформа>.yampkg

# Интерактивная первичная настройка
soloist setup
```

### Standalone (`install.sh`)

Скачайте `soloist-station-lite.tar.gz` из [Releases](https://github.com/Horohi/soloist-station-lite/releases) (в архиве находятся собранный плеер `bin/soloist`, `curl` и системные библиотеки `lib64/`), распакуйте и выполните установку на самой колонке:

```bash
adb connect <IP_КОЛОНКИ>:5555
tar -xzf soloist-station-lite.tar.gz
adb push soloist-station-lite /data/local/tmp/soloist-station-lite
adb shell "cd /data/local/tmp/soloist-station-lite && sh ./install.sh"
```

Ключ и имя устройства можно передать сразу аргументами: `sh ./install.sh <API_KEY> "<Имя устройства>"`.

### Подключение в Spotify

Откройте Spotify на телефоне или компьютере, перейдите в меню выбора устройств и выберите вашу колонку.

## Настройка

Основную конфигурацию выполняет мастер `soloist setup`:

- **Ключ Soloist и имя устройства:** сохраняются в `/data/yam/etc/horohi.soloist/config.env` (YAM v2) или `/data/opt/soloist/start.sh` (Standalone).
- **Spotify Web API (`spotify_api.conf`):** `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET` и при необходимости рынок аккаунта `SPOTIFY_MARKET="DE"` (пример — `spotify_api.conf.example`).
- **Избранное (`favorites.uri`):** Spotify не даёт внешней ссылки для запуска системного раздела «Любимые треки» с нуля. Внутренний URI коллекции умеет только возобновлять уже загруженную очередь, поэтому для команды *«включи любимые треки»* создайте отдельный обычный плейлист и укажите его ссылку в `soloist setup`.
- **Параметры звука (`config.env`):** для Лайт 2 (`plum`) по умолчанию выставляется `APULSE_PLAYBACK_DEVICE=sysdefault:CARD=<CARD>` и `APULSE_EXTERNAL_VOLUME=0`; переопределения в `config.env` сохраняются при запуске службы.

## Голосовые команды и кнопки

### Воспроизведение и поиск

| Фраза Алисе | Действие |
| --- | --- |
| *«Включи песню ...»*, *«Поставь [исполнитель] [трек]»* | Поиск и запуск трека |
| *«Включи группу ...»*, *«Включи альбом ...»* | Запуск исполнителя или альбома |
| *«Включи плейлист ...»* | Поиск публичного плейлиста по точному названию |
| *«Включи любимые треки»* / *«Избранное»* | Запуск плейлиста из `favorites.uri` (или текущей коллекции) |
| *«Включи волну»* / *«Радио»*, *«Включи волну по треку ...»* | Запуск радио по текущему или указанному треку |
| *«Включи музыку»* / *«Играй»* / *«Продолжи»* | Возобновление воспроизведения |
| *«Пауза»* / *«Стоп»* | Пауза |
| *«Дальше»*, *«Назад»* | Переключение трека |
| *«Перемешай»* / *«По порядку»* | Включить или выключить Shuffle |
| *«Повторяй»* / *«Не повторяй»* | Повтор трека |
| *«Что играет»* | Озвучивание текущего трека |
| *«Громче»* / *«Тише»* / *«Громкость N»* | Регулировка громкости колонки |

При переключении на Яндекс Музыку (*«включи Яндекс Музыку»*, *«мою волну в Яндексе»*) активный Spotify ставится на паузу без подавления Алисы, а команды *«дальше»*, *«назад»* и *«что играет»* передаются Алисе до возврата в Spotify.

### Цензура и LED-подсветка

| Фраза Алисе | Действие |
| --- | --- |
| *«Без мата»* / *«Включи цензуру»* / *«Детский режим»* | Искать только Clean-версии треков |
| *«С матом»* / *«Выключи цензуру»* / *«Взрослый режим»* | Разрешить треки Explicit |
| *«Зажигай»* / *«Эквалайзер»* / *«Светомузыка»* | Включить аудио-подсветку кольца |
| *«Стоп эквалайзер»* / *«Погаси подсветку»* | Выключить подсветку |

При включённой цензуре поиск по альбому, исполнителю и плейлисту блокируется, так как API не проверяет состав подборок целиком.

### Кнопки на корпусе

- Короткое нажатие центральной кнопки: Play / Pause.
- Удержание центральной кнопки: штатный вызов Алисы.
- Кнопки `+` / `-`: регулировка громкости (двусторонняя синхронизация со Spotify).

## Команды CLI

Утилита `soloist` доступна на колонке по SSH/ADB:

| Команда | Назначение |
| --- | --- |
| `soloist setup` | Мастер настройки ключей, имени колонки, избранного и прокси |
| `soloist status` | Статус плеера, моста, сессии Spotify, памяти и текущего трека |
| `soloist network [status\|auto\|off\|check]` | Статус и управление встроенным SNI-прокси для Spotify |
| `soloist doctor [--offline]` | Сводка для баг-репорта без утечки ключей, токенов и запросов |
| `soloist led [on\|off\|white\|rainbow\|cyan\|status]` | Управление LED-эквалайзером и его цветом |
| `soloist start` / `stop` / `restart` | Управление фоновыми службами плеера и моста |
| `soloist logs [bridge\|search]` | Просмотр логов (`soloist`, `bridge` или `search`) |
| `soloist clean` | Очистка временных файлов, старых логов и аудиокэша |
| `soloist update [--force]` | Обновление Standalone-установки с GitHub |
| `soloist version` | Текущая и последняя версия на GitHub |

## Сеть и диагностика

- **SNI-прокси (`soloist network`):** в режиме `auto` скрипт `spotify-network.sh` проверяет доступность `api.spotify.com`, `accounts.spotify.com` и `spclient.wg.spotify.com`, обновляя только собственный блок четырёх доменов Spotify в `/etc/hosts`. Если текущий прокси перестал отвечать и кандидаты недоступны, а прямая сеть работает, мёртвые записи очищаются автоматически. Системный DNS и пользовательские записи в `hosts` не изменяются. Если трафик на Spotify идёт через VPN на роутере, отключите прокси командой `soloist network off`.
- **Отчёты об ошибках (`soloist doctor`):** выводит версию, платформу, состояние служб и сессии Spotify, настройки `hosts`/сети, параметры ALSA и типизированные коды последних событий из логов (`--offline` пропускает внешний запрос к API). Прикладывайте вывод этой команды к issue.

## Сборка из исходников

Кросс-компиляция статического C-моста `soloist-bridge`, ALSA ducking-модуля и ресемплера под `aarch64`:

```bash
make
```

Сборка `.yampkg` для конкретной платформы или всех поддерживаемых целей (требуется `yam-publish`):

```bash
./scripts/pack-yam.sh yandexmicro
./scripts/pack-yam.sh all
```

Тесты на хосте (C-парсеры, логика поиска, сетевой failover, YAM v2, управление):

```bash
sh tests/test_requests.sh
python3 tests/test_yam_mode.py
python3 tests/test_network.py
```
